# Документація API v2: дизайн

## Мета

Неофіційна документація API eRepublik, яку зручно читати прямо на сторінках GitHub.
Читачі: насамперед люди (автор і розробники зі спільноти), також агенти.

**Не мета:** OpenAPI/Swagger, генератори й скрипти збірки, власний хостинг.
**Невдача:** щоб прочитати документацію, треба щось встановити чи запускати.

## Підходи

| Підхід | Компроміс | Рішення |
|---|---|---|
| OpenAPI → згенерований Markdown | строгі схеми, але треба підтримувати генератор | відхилено: не хочемо генераторів |
| HTML | вільне оформлення, але GitHub показує `.html` у репо як сирий код | відхилено |
| Markdown, написаний вручну | просто й читабельно, але формат тримається лише на шаблоні | **обрано** |

## Структура

```
v2/
  README.md                 ← вхід: меню як у грі, посилання на тематичні сторінки
  guides/
    daily-routine.md        ← сценарій із посиланнями (робота, тренування, енергія, нагороди)
    …                       ← авторизація, CSRF, ID
  military/
    README.md               ← огляд і карта модуля
    battlefield/
      README.md             ← порядок бою (Mermaid), список ендпоінтів
      joining.md            ← вибір сторони, переліт, дивізіон
      deployment.md         ← інвентар, старт, скасування, енергія
      combat-extras.md      ← бустери, бомби, ефекти
      stats.md              ← консоль і статистика бою
      websocket.md
    campaigns.md            ← вкладка Wars: списки битв, фільтри, пресети
    wars.md                 ← сторінка війни, підтримка RW
    armory.md
    training.md             ← тренувальні майданчики
    pvp.md
    military-unit.md        ← якщо знайдемо ендпоінти в коді гри
  reference/
```

- Сторінка = тема або екран гри; пов'язані ендпоінти описані разом.
- Підпапка з'являється, лише коли тема не вміщається в одну зручну сторінку.
- Кожен ендпоінт описаний рівно один раз; інші місця тільки посилаються на нього.
- Меню як у грі (зокрема My places) відтворюється посиланнями в README, а не папками.

## Тематична сторінка

1. Назва, «хлібні крихти», 2–3 речення про екран.
2. Зміст: таблиця ендпоінтів сторінки (метод, URL, дія, статус).
3. Розділ на кожен ендпоінт: метод і URL, авторизація, статус; призначення; параметри і
   короткий cURL; скорочений приклад відповіді та таблиця полів (повний приклад у `<details>`);
   помилки; пастки (`> [!WARNING]` для дій, що витрачають ресурси); джерело в коді гри.

Спільні заголовки й `_token` описані один раз у `guides/`.

**Статус:** `✅ Verified` (перевірено реальним запитом, з датою), `🔍 From code`
(виведено з коду гри) або `❔ Unconfirmed` (походження невідоме).

## Правила

- Документація англійською.
- Лише те, що рендерить GitHub; відносні посилання.
- Без реальних cookie й токенів; баланси валюти та золота завжди `0`.
- Старе переносимо без втрати інформації; суперечності позначаємо, а не вгадуємо.

## Порядок роботи

1. Гілка `docs/v2`, нова папка `v2/`; старі файли поки не чіпаємо.
2. Пілот: `military/deployment` → `v2/military/battlefield/deployment.md`
   (зараз `startDeploy` описаний двічі). Ти оцінюєш вигляд.
3. Затверджений шаблон записуємо в `v2/CONTRIBUTING.md`.
4. Переносимо решту по одному модулю.
5. Наприкінці `v2/` стає коренем, старе видаляється, оновлюються `CLAUDE.md` і скіл `erep-api-doc`.

## Головний README

`v2/README.md` (наприкінці стане кореневим), англійською, 1–3 сторінки A4: що це за проєкт,
будова репо і що де шукати, як читати сторінки, правила оформлення, як відкрити локально,
як контрибʼютити, невеликий блок метрик (оновлюється вручну або бейджами; без скриптів).

## Git

- Малі зміни комітимо прямо в `docs/v2`.
- Великі робимо в окремій гілці (`docs/v2-<тема>`) і вливаємо в `docs/v2`.
- Коли все перенесено, `docs/v2` вливається в `main` і замінює старі файли.

## Сайт (пізніше, необов'язково)

Ті самі `.md` можна показати на GitHub Pages без власних генераторів. Вибір інструмента — після перенесення.

## На розсуд виконавця

Назви файлів, поділ великих тем, довжина прикладів, потрібність схем.
